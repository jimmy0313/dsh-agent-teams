# AgentTeams v0.1.12

This release bakes the second collaboration retrospective (the dsh-remote-mobile relay-protocol project) into the plugin: contract freeze discipline, direct captain rulings, review baselines, and confirmation-loop prevention. The five iteration rules from that retrospective are now plugin mechanisms plus protocol/persona rules, not just advice.

## New

- **`agent_teams_ruling` (captain-only)**: issue a binding decision directly to the task owner and record it in the team's durable ruling log (`r1`, `r2`, …; the latest wins). Precedence on conflict is pinned for members: the contract on disk is the baseline, a ruling overrides it, and the captain's latest ruling wins. Rulings are never relayed through a third member — they are delivered straight to the owner's next turn.
- **Contract freeze gate**: `agent_teams_create_task` accepts `contract=true` to mark the single team contract. Once that task reaches a terminal status the contract is frozen (terminal results are immutable), so revisions need a new generation with a revision header and captain approval. While the contract is unfrozen, creating an implementation task without a dependency on the contract review gate returns a warning nudging the captain to gate it.
- **Terminal finality is enforced end to end**: the scheduler explicitly never re-dispatches terminal tasks, and claim/update paths reject them; verified by regression probes (idle member + empty ready pool ⇒ zero deliveries).
- **Member persona rules**: report each result/blocker exactly once and never send no-new-information confirmations (status is the acknowledgement); treat captain rulings as authoritative with latest-wins precedence; record reviewed file versions (path + mtime/hash) in review task output.
- **Captain protocol updates**: write the contract once after all rulings are issued; require interface-heavy contracts to define protocol literals in one constant module (single source of truth) with a verify gate scanning for hardcoded literals; only reply to messages carrying new information.
- `agent_teams_status` now shows the ruling log, the contract task id, and a `[CONTRACT]` marker per task; the activity snapshot carries a per-task `contract` flag.

## Verification

- Offline verification: rulings/contract state round-trip at the durable boundary, legacy teams without the new fields stay valid, and source scans pin the new protocol promises.
- Lifecycle verification: a dedicated probe team exercises contract freeze (single-owner rejection, nudge before freeze, silence after), direct ruling delivery to the owner, captain-only ruling enforcement, status exposure, and the terminal-never-redispatched guarantee.
- Passed type checking, production build, offline verification, lifecycle verification, and the eight-member complex stress suite.

## Installation

```sh
dsh plugin --profile web add @nanmicoder/dsh-agent-teams
```

# AgentTeams v0.1.12

本次更新把第二次协作复盘（dsh-remote-mobile 中继协议工程）固化进插件：契约冻结门禁、组织者裁定直达、评审基准固定与确认循环抑制。复盘的五条迭代规则从此是插件机制 + 协议/成员 persona 规则，而非一句建议。

## 新增

- **`agent_teams_ruling`（组织者专属）**：把绑定裁定直接发给任务 owner，并写入团队持久化裁定日志（`r1`、`r2`…，最新者优先）。冲突优先级已写死进成员规则：契约以磁盘为准、裁定以队长消息为准、两者冲突时以队长最新裁定为准。裁定绝不经第三方转达——直接投递到 owner 的下一轮。
- **契约冻结门禁**：`agent_teams_create_task` 支持 `contract=true` 标记唯一契约任务；其状态进入终态即冻结（终态不可变），修订只能走「新一代契约 + 修订头 + 组织者批准」。契约未冻结时，创建未依赖契约评审门的实现任务会收到提示。
- **终态终局全链路强制**：调度器显式绝不重派终态任务，claim/update 路径拒绝终态操作；回归探针验证（空闲成员 + 空就绪池 ⇒ 零投递）。
- **成员 persona 规则**：每个结果/阻塞只报告一次，禁止无新信息的确认消息（状态即确认）；队长裁定具有权威性且最新者优先；评审任务输出必须记录被审文件版本（路径 + mtime/哈希）。
- **组织者协议更新**：契约在集齐全部裁定后一次性成稿；接口重型契约要求协议字面量收敛到唯一常量模块（单一事实源）并由 verify 扫描禁止硬编码；只回复有新信息的消息。
- `agent_teams_status` 新增裁定日志、契约任务 id 与每任务 `[CONTRACT]` 标记；活动快照任务行携带 `contract` 字段。

## 验证

- 离线验证：裁定/契约状态在持久化边界往返、无新字段的旧团队仍有效、源码扫描钉住新协议承诺。
- 生命周期验证：独立探针团队演练契约冻结（单一 owner 拒绝、冻结前提示、冻结后静默）、裁定直达 owner、仅组织者可裁定、状态暴露、以及终态绝不重派。
- 通过类型检查、生产构建、离线验证、生命周期验证及八成员复杂压力测试。

dsh plugin --profile web add @nanmicoder/dsh-agent-teams
